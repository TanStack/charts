# TanStack Charts 1.0 readiness

The goal is a stable public API backed by verified published packages. This file
tracks the work and its evidence. An unchecked gate blocks readiness. Publishing
1.0 is a separate release decision after these gates pass.

## Required gates

- [x] Review and integrate portable inferred declarations, issue #156 / PR #157.
      Emit declarations from installed tarballs and compile them downstream.
- [ ] Review and integrate map and polar states, issue #126 / PR #158.
      Verify source ownership, transitions, restoration, renderer behavior,
      and the measured optional bundle costs.
- [ ] Review and integrate adapter lifecycle coverage, PR #155.
      Verify updates, duplicate mounts, teardown, SSR, and hydration.
- [ ] Resolve state ownership for composed datum groups, issue #135.
      One group must own its paint and animation without applying the same
      opacity to every descendant. Cover nested state overrides.
- [ ] Resolve focus styling for tick labels and point-less marks, issue #134.
      Pointer movement must not require rebuilding the chart definition or
      adding hit-test points to decorative geometry.
- [ ] Resolve legend emphasis, issue #127.
      Hover and keyboard emphasis must preserve pinned focus and avoid
      unintended tooltips, crosshairs, and focus-filtered geometry.
- [ ] Publish the 1.0 compatibility contract and support boundaries.
      Cover public types, extension protocols, framework and runtime support,
      deprecations, renderer differences, and explicitly experimental features.
- [ ] Verify the complete candidate with unit, type, documentation, packaged
      consumer, framework, native, and browser conformance checks.
      Include keyboard interaction, reduced motion, SSR/hydration, and export.
- [ ] Verify size and performance against equivalent production builds.
      Record per-entry costs and representative scene, pointer, animation,
      update, and teardown measurements. Keep expensive release checks outside
      routine PR CI.
- [ ] Verify release automation and the versioned release candidate artifacts.
      Check coordinated versions, peer ranges, migrations, package contents,
      installability, and provenance before declaring readiness.

## Performance audit

The standard TanStack stress suite was run sequentially for baseline
`327f488f46463408e91eef4828d54f45017f717d` and candidate
`b2995b26e6e5ce4d51c97903268131713bbe0ac9`. The baseline is retained in
`/private/tmp/charts-one-ready-perf-baseline.JYf28Q` with matching pinned
dependencies installed offline. Workload definitions, measurement scripts,
and TanStack benchmark adapters are unchanged between these revisions.
Both runs used Node 24.18.0 and Chromium 151.0.7922.34 on the same Apple M5 Pro.

Both revisions complete all 20 standard cells with no correctness failures.
Source counts, prepared counts, canonical input digests, update target digests,
and fixed timing sample counts match. All eleven ten-cycle teardown soaks
retain zero additional documents, DOM nodes, or listeners after garbage
collection. Heap deltas remain reported measurements, not a proof of zero
retained JavaScript allocation or GPU/native memory use.

The timing gate remains open. The first pair contains slower candidate
scatter timings. Repeating raw line, raw scatter, and interactive scatter in
reversed candidate/baseline order also completes all six cells correctly,
but several 10,000-dot synchronous updates remain slower across separate
runs: same-data update 35.3 ms to 39.6 ms, append 36.4 ms to 40.7 ms, and
replacement 32.3 ms to 36.6 ms. These are not approved regressions.

Interleaved diagnostic trials do not establish the same difference. With
10,000 dots, 21 alternating blocks, and five operations per block, initial
scene compilation and SVG serialization differ by less than 1%. A mounted
diagnostic with both 800 by 400 charts fully visible produces median updates
of 34.3 ms for baseline and 34.9 ms for candidate, with identical DOM output.
This fixture differs from the stress suite's fresh-context update trials,
so it does not clear the repeated stress slowdown or identify its cause.
The earlier vertically stacked mounted diagnostic partly clipped its second
chart and is not used as equivalent-layout evidence.

Reproduction uses `node scripts/stress-chart-libraries.mjs --library=tanstack
--profile=standard` in each checkout, one run at a time. The reversed-order
repeat adds `--workload=raw-scatter,interactive-scatter,raw-line`.
Original full results are retained at
`/private/tmp/charts-ready-stress-baseline-full-1.json` and
`/private/tmp/charts-ready-stress-candidate-full-1.json`; paired summaries are
`/private/tmp/charts-ready-stress-pair.json` and
`/private/tmp/charts-ready-stress-repeat-pair.json`. Diagnostic fixtures and
results are retained in `/private/tmp/charts-ready-scene-pair.mjs`,
`/private/tmp/charts-ready-scene-pair.json`, and
`/private/tmp/charts-ready-visible-mounted-pair.json`.
No routine CI jobs or budgets were changed for this audit.

A follow-up uses the exact stress timing function and compiled production
bundles in six alternating baseline/candidate pairs, each in a fresh browser
context with the same 1,400 by 900 viewport. For the 10,000-dot same-data
update, with three warmups and twenty samples per trial, the median of trial
medians is 37.85 ms for baseline and 38.65 ms for candidate, a 0.80 ms or 2.1%
increase. Source and target digests and output probes match. Results are retained
in `/private/tmp/charts-ready-exact-stress-pair.json` and the diagnostic is
`/private/tmp/charts-ready-exact-stress-pair.mjs`. This more controlled comparison
weakens evidence for the larger separate-run slowdown, but does not prove
unchanged performance or cover other update, pointer, and animation phases.

Two tick-opacity allocation experiments were discarded after size measurement.
Both avoid cloning the cold focus context for constant opacity, but increase
measured consumer bundles relative to the existing candidate. The existing

in `/private/tmp/charts-ready-tick-before-size.log`,
`/private/tmp/charts-ready-tick-after-size.log`, and
